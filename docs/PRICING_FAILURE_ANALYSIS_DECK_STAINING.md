# Pricing Failure Analysis - Deck Staining Estimate

## Purpose

This document records the confirmed root cause of the EST-0016 deck-staining pricing failure and defines the safe implementation path. It does not change runtime behavior, pricing, proposal output, approval workflow, database schema, AI behavior, or existing estimate records.

## Source Case

Observed estimate:

- Estimate: `EST-0016`
- Intended scope: deck staining / deck refinishing
- Expected quantity basis: main deck walking surface, approximately `250 sf`
- Expected work: power washing, dry time / return trip, sanding or prep, stain/sealer material, stain/sealer application labor, protection, and cleanup

Expected optional scope only when confirmed:

- Railings
- Stairs
- Heavy sanding or stripping
- Minor board, railing, or fastener repair
- Furniture moving
- Premium stain product or second coat

## Observed Bad Generated Lines

The estimate generated broad remodel trades:

| Generated item | Observed qty/unit | Why it is wrong for deck staining |
|---|---:|---|
| Framing | 250 sf | Not part of staining unless repairs are explicitly confirmed |
| Drywall | 250 sf | Interior trade; should not appear in deck staining |
| Electrical | 250 sf | Unrelated unless exterior electrical work is requested |
| Flooring Labor | 250 sf | Interior flooring trade; deck staining needs wood finishing labor |
| Flooring Underlayment/Consumables | 250 sf | Interior flooring material category |
| Demo & Protection | 250 sf | Protection may apply, but generic demo is not the same as deck masking/protection |
| Paint Labor | 250 sf | Related only by finish concept; should be deck stain/sealer application |
| Paint Materials | 250 sf | Related only by finish concept; should be stain/sealer material |
| Plumbing | 250 sf | Unrelated |
| HVAC | 250 sf | Unrelated |

## Confirmed Root Cause

The failure came from deterministic cost-library selection, not AI output.

Current generation path:

1. The estimate is classified through legacy `project_type`.
2. Deck-staining-specific classification does not exist.
3. Unmapped/custom/exterior categories can fall back to `Full Rehab`.
4. `runCostEngine()` selects default included cost-library rows where `project_type === 'Full Rehab'`.
5. The seeded `Full Rehab` cost library contains the unrelated remodel rows listed above.
6. Each row with `qty_rule = 'sqft'` receives `input.sqft`, so `250` is copied into every selected square-foot row.
7. Generated rows are saved with `source = 'CostLibrary'`.
8. Public PDF inclusion defaults behave as checked unless explicitly set false.

## Specific Findings

### Wrong line origins

The wrong lines originate from seeded `Full Rehab` rows in the cost library. They are not generated by an AI model, not expanded from a deck assembly, and not manually selected by a deck-specific service workflow.

### Quantity propagation

The same `250 sf` quantity appears because cost-library rows with `qty_rule = 'sqft'` use the estimate's `sqft` value as their line quantity.

### Unit assignment

Rows with `qty_rule = 'sqft'` are converted to line-item unit `sf`.

### Source label

Generated deterministic rows are labeled `CostLibrary`.

### Phase assignment

The current line-item table has a database default of `Other`, and manual/AI fallback paths may also use `Other`. Current cost-engine phase resolution should map many seeded Full Rehab rows to their actual trade phase, so an all-`Other` EST-0016 view likely reflects older persisted rows, fallback insertion, or previously generated data before current phase mapping.

### PDF default

Public PDF checkboxes default to checked because the line-item database column, row mapping, upsert behavior, and UI checkbox all treat missing `include_in_public_pdf` as true unless explicitly false.

## TVIK Rule Impact

This is a deterministic pricing and classification failure. It does not appear to be an AI mutation failure, but it can still create client-facing risk if not blocked before proposal review.

Impacted controls:

- Deterministic pricing selected the wrong cost-library rows.
- Estimate record remains source of truth, but the saved line items may be wrong.
- Public PDF defaults can expose wrong rows unless manually unchecked.
- Health checks do not yet detect deck-staining scope mismatch.

Not fixed by this document:

- Runtime generation behavior
- Pricing calculations
- PDF behavior
- Existing EST-0016 data
- Approval/status workflow
- AI suggestion workflow

## Immediate Safe Target

The first runtime patch should not rewrite pricing. It should prevent or warn against contaminated deck-staining estimates.

P0 behavior to design:

- Detect likely deck-staining scope.
- Warn if blocked trades appear.
- Do not approve or send client-facing output with high-severity mismatch.
- Do not silently delete or rewrite existing line items.
- Preserve human review and auditability.
